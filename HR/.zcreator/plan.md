A secure internal onboarding app for HR, IT, and hiring managers. It centralizes new-hire records, role-based checklists, identity documents, hosted training videos, handbook acknowledgements, progress dashboards, and scheduled overdue reminders at 1, 3, and 7 days.

## User Profiles

Establish separate access profiles for Human Resources, IT support, and hiring managers. New hires will not receive application accounts; HR will facilitate uploads, training, and sign-off activities with them.

Create shell custom profile files only (name and type; no ModulePermissions yet): Human_Resources (type Custom) intended for full onboarding administration and sensitive document access; IT_Support (type Custom) intended to manage IT checklist tasks without access to IDs or handbook signatures; Hiring_Manager (type Custom) intended to view assigned hires and manage manager checklist tasks without access to identity documents. Do not create a new-hire profile, portal profile, roles, or sharing rules. Do not emit default profiles.

## New_Hires

Maintain the central onboarding record for each incoming employee, including contact details, start information, responsible internal contacts, and overall progress.

Create stateful form New_Hires with: Onboarding_Details section; Employee_ID autonumber starting at 1001; Full_Name text must have; Personal_Email email must have unique and personal data; Phone phonenumber personal data; Job_Title text must have; Department picklist must have with values Human Resources, Information Technology, Finance, Sales, Marketing, Operations, Legal, Other; Start_Date date must have; Manager_Name text must have; Manager_Email email must have; HR_Owner_Email email must have; IT_Owner_Email email must have; Status picklist must have with values Pre-boarding, In Progress, Awaiting Sign-off, Complete, On Hold and initial value Pre-boarding; Notes textarea. Use medium width consistently and standard add/edit actions. Create default list report All_New_Hires showing Employee_ID, Full_Name, Personal_Email, Job_Title, Department, Start_Date, Manager_Name, Status, grouped by Status and sorted by Start_Date descending. Create list report Active_Onboarding showing records whose Status is not Complete, with the same operational fields and filters for Department, Start_Date, Status. Workflow New_Hires_On_Success triggers on add success: fetch all active Checklist_Templates and create one Onboarding_Tasks record per template, assigning Assignee_Email from HR_Owner_Email, IT_Owner_Email, or Manager_Email based on template Category; set Due_Date to Start_Date plus Offset_Days; copy task name, category, description, and priority; initialize Status to Not Started. In the same workflow fetch all active Training_Content records and create Training_Assignments due on Start_Date plus each content item Due_Offset_Days, initialized to Assigned. Follow safe fetch/count patterns and avoid nested queries.

## Checklist_Templates

Let HR define reusable onboarding steps for IT, HR, and managers so every new hire receives a consistent checklist.

Create stateful form Checklist_Templates with: Template_Details section; Task_Name text must have; Category picklist must have with values HR, IT, Manager; Description textarea must have; Offset_Days number must have with initial value 0; Priority picklist must have with values Low, Normal, High, Critical and initial value Normal; Active checkbox with initial value true. Create default list report All_Checklist_Templates showing Task_Name, Category, Offset_Days, Priority, Active, grouped by Category and sorted by Task_Name ascending, with filters Category, Priority, Active. No workflows.

## Training_Content

Store the onboarding video library and control which training items are automatically assigned to incoming employees.

Create stateful form Training_Content with: Content_Details section; Training_Title text must have unique; Description textarea must have; Training_Video video must have with appropriate upload/browse configuration; Duration_Minutes number; Due_Offset_Days number must have with initial value 0; Mandatory checkbox with initial value true; Active checkbox with initial value true. Create default list report Training_Library showing Training_Title, Description, Duration_Minutes, Due_Offset_Days, Mandatory, Active, sorted by Training_Title ascending, with filters Mandatory and Active. Human Resources manages records; IT Support and Hiring Manager receive read-only report access in the Permissions segment. No workflows.

## Onboarding_Tasks

Track each hire’s actionable HR, IT, and manager checklist items, with clear ownership, due dates, priorities, and completion status.

Create stateful form Onboarding_Tasks with: Task_Details section; New_Hire lookup must have to New_Hires.ID displaying Full_Name; Task_Name text must have; Category picklist must have with values HR, IT, Manager; Description textarea; Assignee_Email email must have; Due_Date date must have; Priority picklist must have with values Low, Normal, High, Critical; Status picklist must have with values Not Started, In Progress, Blocked, Complete and initial value Not Started; Completion_Date date; Completion_Notes textarea; Last_Reminder_Date date; Reminder_Level number with initial value 0. Create default list report All_Onboarding_Tasks showing New_Hire, Task_Name, Category, Assignee_Email, Due_Date, Priority, Status, Completion_Date, grouped by Category and sorted by Due_Date ascending, with filters Category, Assignee_Email, Priority, Status. Create kanban report Onboarding_Task_Board grouped by Status showing New_Hire, Task_Name, Category, Assignee_Email, Due_Date, Priority with record counts and filters Category, Assignee_Email, Priority. Create calendar report Onboarding_Due_Calendar with display field Task_Name, start date Due_Date, showing New_Hire, Category, Assignee_Email, Priority, Status and filters Category, Assignee_Email, Status. Workflow Task_Status_On_User_Input on user input/update of Status: show Completion_Date and Completion_Notes only when Status is Complete, otherwise hide them. Workflow Onboarding_Tasks_On_Load sets the same visibility when the form opens. Workflow Onboarding_Tasks_On_Success on add/edit success sets Completion_Date to current date when status becomes Complete, clears it when reopened, and checks whether the related hire has any incomplete onboarding tasks, incomplete mandatory training assignments, or no handbook acknowledgement; if none remain, update New_Hires.Status to Complete, otherwise set it to In Progress or Awaiting Sign-off as appropriate. Create daily form schedule Overdue_Task_Reminders on Onboarding_Tasks: process records where Due_Date is before current date and Status is not Complete; calculate days overdue and send email at exactly 1, 3, and 7 days to Assignee_Email, updating Last_Reminder_Date and Reminder_Level to prevent duplicate sends; on day 7 also copy the related hire's HR_Owner_Email. Include hire name, task, due date, days overdue, and a link to the task report in the email. Use guarded fetches and batch-safe processing.

Securely capture and verify one or more identity documents for each incoming employee while keeping them hidden from IT and managers.

Create stateful form ID_Documents with: Document_Details section; New_Hire lookup must have to New_Hires.ID displaying Full_Name; Document_Type picklist must have with values Passport, National ID, Driver License, Tax Document, Work Authorization, Other; Document_File upload file must have, personal data, encrypted storage, browse enabled, file count 1; Expiry_Date date; Verification_Status picklist must have with values Pending, Verified, Rejected and initial value Pending; Verified_By email; Verified_Date date; Verification_Notes textarea. Create default list report ID_Document_Register showing New_Hire, Document_Type, Expiry_Date, Verification_Status, Verified_By, Verified_Date, sorted by New_Hire ascending, with filters Document_Type and Verification_Status. Workflow Verification_Status_On_User_Input on user input/update of Verification_Status: show and enable Verified_By and Verified_Date only when status is Verified; otherwise hide them. Workflow ID_Documents_On_Load applies the same state on form open. Workflow ID_Documents_On_Success sets Verified_By to zoho.loginuserid and Verified_Date to current date when Verification_Status becomes Verified. Access to this form/report and all fields is Human_Resources only; IT_Support and Hiring_Manager receive no module/report access.

Assign required videos to each hire and record completion as HR facilitates onboarding sessions.

Create stateful form Training_Assignments with: Assignment_Details section; New_Hire lookup must have to New_Hires.ID displaying Full_Name; Training_Item lookup must have to Training_Content.ID displaying Training_Title; Due_Date date must have; Status picklist must have with values Assigned, In Progress, Completed, Waived and initial value Assigned; Completed_Date date; Facilitated_By email; Completion_Notes textarea. Create default list report Training_Assignment_Register showing New_Hire, Training_Item, Due_Date, Status, Completed_Date, Facilitated_By, grouped by Status and sorted by Due_Date ascending, with filters New_Hire, Status, Due_Date. Create list report Outstanding_Training showing records whose Status is neither Completed nor Waived, with New_Hire, Training_Item, Due_Date, Status and filters New_Hire, Due_Date, Status. Workflow Training_Status_On_User_Input on user input/update of Status shows Completed_Date and Facilitated_By for Completed or Waived and hides them otherwise. Human Resources can edit; managers can view; IT has no access unless granted read-only to the outstanding report.

## Onboarding_Dashboard

Provide an at-a-glance command center for onboarding progress, overdue work, upcoming starts, training, and handbook completion.

Create page Onboarding_Dashboard using a polished HTML snippet-based layout under pages/Onboarding_Dashboard/. Use ZCS components and include zcs-global.css once. The main Onboarding_Dashboard_page.ds content must reference child files only and must not inline element definitions. Build responsive KPI cards for active hires, overdue tasks, tasks due in the next 7 days, and completed onboardings; status-distribution visualization; task ownership/category breakdown; upcoming start-date list; overdue-task table with severity badges; outstanding training table; and recent handbook acknowledgements. Include clear links to Active_Onboarding, Onboarding_Task_Board, Onboarding_Due_Calendar, Outstanding_Training, and Handbook_Signoff_Register. Use server-side Deluge in the snippet for safe counts and bounded record lists, with null guards. Do not expose identity document data on the dashboard.

## Permissions

Apply complete role-based access so HR administers the process, IT sees only IT work, and managers see only their onboarding responsibilities and safe employee metadata.

Read all generated form and report files, then edit the Human_Resources, IT_Support, and Hiring_Manager profile shells to add complete ModulePermissions, FieldPermissions, ReportPermissions, and page access. Human_Resources: full CRUD on all forms and reports, including ID documents, signatures, videos, templates, tasks, and dashboard. IT_Support: read New_Hires operational fields but hide Personal_Email, Phone, HR_Owner_Email, and sensitive notes where appropriate; read Training_Library; read/edit Onboarding_Tasks operational fields for IT work but no delete; no access to ID_Documents or Handbook_Acknowledgements; no access to signature/file fields; dashboard access. Hiring_Manager: read New_Hires operational fields, with Personal_Email and Phone read-only only if needed for onboarding contact; read Training_Library and Training_Assignments; read/edit manager Onboarding_Tasks with no delete; read Handbook_Signoff_Register metadata but hide Handbook_File and Employee_Signature; no ID_Documents access; dashboard access. Templates are full access for HR and read-only for IT/managers. Configure button permissions conservatively. No roles or sharing rules.
