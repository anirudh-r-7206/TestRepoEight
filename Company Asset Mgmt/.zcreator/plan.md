Build an IT-admin-only hardware custody app for laptops, monitors, and other company equipment. It will show each asset’s current holder and condition while preserving assignment and maintenance history as separate records, with automated consistency checks and a concise operations dashboard.

## User Profiles

Use the platform’s built-in administrator access for the IT team. No employee self-service or manager access will be exposed in this version.

Profiles: use the default Administrator profile only because the app is IT-admin-only. Do not create a custom profile file and do not create roles or sharing rules. This segment establishes that all forms, reports, pages, workflows, and actions are intended only for Administrator users; the later Permissions segment will converge explicit module, field, report, and page access if the DS permission model requires a written profile.

## Assets

Maintain one authoritative inventory record per hardware item, including identifying details, serial number, condition, availability, and current holder. The current assignment fields are system-maintained from custody transactions.

Create stateful form Assets with title/display name “Assets” and standard add/edit actions. Fields and modifiers: Asset_Details section; Asset_ID autonumber start index 1, visible; Asset_Tag text, must have, unique, max 100; Asset_Type picklist, must have, values Laptop, Monitor, Desktop, Tablet, Mobile Phone, Dock, Peripheral, Other; Manufacturer text, must have, max 100; Model text, must have, max 150; Serial_Number text, must have, unique, max 150; Custody_Status section; Condition picklist, must have, values New, Good, Fair, Damaged, Unusable, initial Good; Asset_Status picklist, must have, values Available, Assigned, In Maintenance, Retired, Lost, initial Available; Current_Holder Creator user selector, optional, intended to reference an existing Zoho Creator user and maintained by workflows; Current_Assignment_ID number, optional, system-maintained helper; Notes textarea, optional. Keep widths consistent and use valid section layout rules.
Reports: default list All_Assets from Assets showing Asset_ID, Asset_Tag, Asset_Type, Manufacturer, Model, Serial_Number, Condition, Asset_Status, Current_Holder; filters Asset_Type, Condition, Asset_Status, Current_Holder; group by Asset_Type; sort Asset_Tag ascending. List Available_Assets from Assets where Asset_Status == “Available”, showing identifying fields and condition, sorted Asset_Tag. List Assigned_Assets from Assets where Asset_Status == “Assigned”, showing Asset_Tag, Asset_Type, Serial_Number, Current_Holder, Condition, sorted Current_Holder then Asset_Tag. List Maintenance_Assets from Assets where Asset_Status == “In Maintenance”, showing Asset_Tag, Asset_Type, Serial_Number, Condition, sorted Asset_Tag. All reports are Administrator-only.
Workflows: Assets_On_Validate on add/edit validates status/current-holder consistency: Assigned requires Current_Holder; Available, In Maintenance, Retired, Lost must not retain Current_Holder unless a custody workflow is in the middle of synchronizing the record. Protect Current_Assignment_ID as system-managed and prevent direct status changes that would contradict an active Assignment record. Assets_On_Load disables Current_Holder and Current_Assignment_ID so administrators update custody through Assignments rather than editing the snapshot directly.

**Implementation notes:** Define Assets before Assignments and Maintenance because both use asset lookups. Use declarative uniqueness and mandatory modifiers; do not replace them with validation workflows.

## Assignments

Record every issue and return transaction so IT can see who has an item now and everyone who held it previously. Automated checks prevent overlapping active assignments and synchronize the asset snapshot.

Create stateful form Assignments with title/display name “Asset Assignments” and standard add/edit actions. Fields and modifiers: Assignment_Details section; Assignment_ID autonumber start index 1, visible; Asset lookup picklist to Assets.ID, must have, displayformat Asset_Tag, searchable; Assigned_To Creator user selector, must have, referencing an existing Zoho Creator user; Assigned_Date date, must have, initial zoho.currentdate; Condition_On_Issue picklist, must have, values New, Good, Fair, Damaged, Unusable; Assignment_Status picklist, must have, values Active, Returned, initial Active; Return_Details section; Return_Date date, optional; Condition_On_Return picklist, optional, values New, Good, Fair, Damaged, Unusable; Assignment_Notes textarea, optional; Return_Notes textarea, optional. Keep widths consistent and valid section rows.
Reports: default list Assignment_History from Assignments showing Assignment_ID, Asset, Assigned_To, Assigned_Date, Assignment_Status, Return_Date, Condition_On_Issue, Condition_On_Return; filters Asset, Assigned_To, Assignment_Status; group by Asset; sort Assigned_Date descending. List Active_Assignments where Assignment_Status == “Active”, showing Asset, Assigned_To, Assigned_Date, Condition_On_Issue; filters Asset and Assigned_To; sort Assigned_Date descending. List Returned_Assignments where Assignment_Status == “Returned”, showing full issue/return details; filters Asset and Assigned_To; sort Return_Date descending. All reports are Administrator-only.
Workflows: Assignments_On_Load defaults Condition_On_Issue from the selected asset when available; when editing an Active record, show/enable return fields, and when the record is Returned disable custody-defining fields to preserve history. Asset_On_User_Input reacts to Asset selection by copying the asset’s current Condition and alerting when status is not Available. Assignments_On_Validate runs on add/edit: an Active assignment is allowed only when the asset is Available and has no other Active assignment; Assigned_Date cannot be in the future; Returned requires Return_Date and Condition_On_Return; Return_Date cannot precede Assigned_Date; prevent changing Asset or Assigned_To after creation; prevent reopening a Returned record. Assignments_On_Success runs on add/edit: for Active, update the linked Asset Current_Holder to Assigned_To, Current_Assignment_ID to this Assignment ID, Asset_Status to Assigned, and Condition to Condition_On_Issue; for Returned, clear Current_Holder and Current_Assignment_ID, set Asset_Status to Available unless an open maintenance record requires In Maintenance, and update Condition from Condition_On_Return. Do not delete historical assignment records as part of any workflow.

**Implementation notes:** The history form is the custody audit trail; do not delete or overwrite old records. Use a searchable lookup to Assets and a Creator user selector for the assignee.

## Maintenance

Track repairs and servicing for each item, including issue details, dates, provider, cost, and condition changes. Open maintenance automatically marks equipment unavailable without losing its custody history.

Create stateful form Maintenance with title/display name “Hardware Maintenance” and standard add/edit actions. Fields and modifiers: Service_Details section; Maintenance_ID autonumber start index 1, visible; Asset lookup picklist to Assets.ID, must have, displayformat Asset_Tag, searchable; Reported_Date date, must have, initial zoho.currentdate; Maintenance_Status picklist, must have, values Open, In Progress, Completed, Cancelled, initial Open; Issue_Description textarea, must have; Service_Provider text, optional, max 150; Service_Cost decimal, optional, decimalplace 2; Condition_Before picklist, must have, values New, Good, Fair, Damaged, Unusable; Resolution_Details section; Started_Date date, optional; Completed_Date date, optional; Work_Performed textarea, optional; Condition_After picklist, optional, values New, Good, Fair, Damaged, Unusable; Notes textarea, optional.
Reports: default list Maintenance_History showing Maintenance_ID, Asset, Reported_Date, Maintenance_Status, Issue_Description, Service_Provider, Service_Cost, Completed_Date, Condition_Before, Condition_After; filters Asset and Maintenance_Status; group by Asset; sort Reported_Date descending. List Open_Maintenance where status is Open or In Progress, showing Asset, status, issue, dates, provider, condition before; filters Asset and status; sort Reported_Date descending. All reports are Administrator-only.
Workflows: Maintenance_On_Load defaults Condition_Before from the chosen Asset and reveals completion fields when status is Completed. Maintenance_Asset_On_User_Input copies the asset’s current condition. Maintenance_Status_On_User_Input shows/enables completion fields only for Completed and keeps them hidden/disabled otherwise. Maintenance_On_Validate requires Completed_Date, Work_Performed, and Condition_After when Completed; validates Started_Date is not before Reported_Date and Completed_Date is not before either Reported_Date or Started_Date; prevents opening a second non-cancelled, non-completed maintenance record for the same asset. Maintenance_On_Success sets the linked Asset status to In Maintenance for Open/In Progress. On Completed, update Asset.Condition to Condition_After and set Asset_Status to Assigned if an Active Assignment exists, otherwise Available; preserve Current_Holder when an active assignment exists. On Cancelled, restore Assigned or Available based on active assignment without changing condition.

## Hardware_Overview

Provide IT with a single operational view of inventory totals, assignment state, condition risks, current holders, and open repairs. The page prioritizes fast scanning and direct navigation to the underlying records.

Create page Hardware_Overview with display name “Hardware Overview”, Administrator-only. Build a responsive dashboard primarily as a .dshtml or .zml snippet using ZCS styling. Include KPI cards for Total Assets, Available, Assigned, In Maintenance, Damaged/Unusable, and Active Assignments. Include an asset-status distribution visualization, an asset-type distribution visualization, a condition-risk summary, a compact current-custody table showing Asset Tag, Type, Serial Number, Current Holder, and Condition, and an open-maintenance list showing Asset, Status, Issue, and Reported Date. Include prominent navigation actions to All_Assets, Active_Assignments, Assignment_History, and Open_Maintenance. Use status badges, clear empty states, accessible contrast, and responsive behavior. Query live data from Assets, Assignments, and Maintenance in inline Deluge. The main Hardware_Overview_page.ds must contain only the page declaration, layout wrappers, and file references; authoritative snippet content belongs under pages/Hardware_Overview/content/.

**Implementation notes:** Use ZCS components and a responsive HTML or ZML snippet rather than a collection of native page components unless a native embed is necessary. Keep the parent page content limited to file references and layout wrappers.

## Permissions

Lock the completed app to IT administrators and ensure every form, field, report, workflow action, and dashboard has the intended access. No employee-facing access is granted.

Converge permissions after all components exist. Use only the default Administrator profile unless the platform export requires an explicit profile declaration; do not create roles or sharing rules. Grant Administrator full add, view, edit, delete, import, and export access to Assets, Assignments, and Maintenance; full field visibility and edit access except system-maintained fields Current_Holder and Current_Assignment_ID should be treated as workflow-controlled in the UI; full access to All_Assets, Available_Assets, Assigned_Assets, Maintenance_Assets, Assignment_History, Active_Assignments, Returned_Assignments, Maintenance_History, and Open_Maintenance; and access to Hardware_Overview. Do not grant access to any other profile. Read the completed form and report files before emitting ModulePermissions so every field and report is included.

## UI Configuration

Organize the app into clear Inventory, Custody, and Maintenance navigation areas with consistent report previews and detail layouts. The dashboard will be the primary landing point for IT.

Create web UI configuration for all completed components. devices/web/forms.ds maps Assets, Assignments, and Maintenance with top label placement. devices/web/menu-sections.ds defines a primary IT Asset Management space with sections: Overview containing page Hardware_Overview; Inventory containing form Assets plus reports All_Assets, Available_Assets, Assigned_Assets, Maintenance_Assets; Custody containing form Assignments plus reports Active_Assignments, Assignment_History, Returned_Assignments; Maintenance containing form Maintenance plus reports Open_Maintenance and Maintenance_History; and mandatory SharedAnalytics_Section. Use valid documented icons. Create devices/web/theme.ds with a professional neutral blue/teal IT operations theme and readable typography.
For every report without exception, create components/<Form>/reports/<Report>/devices/web.ds with valid quickview and detailview layouts. Fields must exist in the report’s show-all-rows definition. All_Assets quickview prioritizes Asset_Tag, Asset_Type, Serial_Number, Asset_Status, Current_Holder, Condition; detailview includes every report column. Available_Assets, Assigned_Assets, and Maintenance_Assets prioritize identity, status/holder, and condition. Assignment reports prioritize Asset, Assigned_To, dates, status, and issue/return conditions. Maintenance reports prioritize Asset, status, issue, dates, provider, cost, and before/after condition. No phone or tablet configuration is required for this IT-admin-only first version.
